---

PlateRelay 专为黑客松、创客空间、高校实验室等公共共享场景设计，核心目标是在提供高效率排队与集中管控的同时，将普通用户与物理设备彻底隔离。

## 核心设计原则

1. **角色与设备隔离**：普通用户仅上传 `.gcode.3mf` 文件并凭取件码核销领取成品，不直接接触打印机局域网或设备控制后台。
2. **面板与 Daemon 分离**：管理面板部署在中心节点；局域网守护进程（daemon）部署在打印机内网并主动通过 WebSocket 连接面板，无需开放任何内网入站端口。
3. **契约先行（Contract-First）**：所有 REST API、SSE 推送与 daemon 协议消息均由 `packages/shared/schema/` 统一生成双端类型与校验逻辑。
4. **清床释放闭环**：打印结束不会立即释放设备，必须由工作人员取下成品入库并确认清床后，打印机才重新进入可派单状态。

## Monorepo 目录结构

| 目录 | 说明 |
| --- | --- |
| `apps/server` | 面板后端服务（`NestJS`、PostgreSQL/PGlite、SSE 实时推送、daemon 控制通道） |
| `apps/web` | 面板前端应用（`React`、`Vite`、`Tailwind CSS`） |
| `daemon` | 局域网设备守护进程（`platerelay_daemon`）与内置模拟打印机（`platerelay_sim`） |
| `packages/shared` | 跨端共享类型、`openapi.yaml` 与 daemon 通信协议契约（`daemon/v1`） |
| `tools` | 硬件只读探测脚本与打印机调试 MCP / TUI 工具 |

## 核心业务流程

1. **提交与校验**：用户上传切片后的 `.gcode.3mf`，服务端工作线程解析参数并校验安全性。
2. **人工审核**：审核员检查模型与切片信息后决定通过或驳回。
3. **规则调度**：通过审核的订单进入队列，系统按规则匹配空闲且兼容的打印机派单。
4. **现场执行**：daemon 下载文件并传输到打印机，完成开打前检查后启动打印并持续回传状态遥测。
5. **入库、清床与取件**：工作人员取件入库并确认清床释放设备，用户凭取件码核销完成交付。
